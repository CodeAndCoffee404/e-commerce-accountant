# Как расширять систему

Ответ на вопрос «отключать существующее можно, а как добавлять новое?».

## Что меняется без кода, прямо в приложении

| Что | Где |
| --- | --- |
| Включить/выключить отчёт | Settings → Reports |
| Канал или маркетплейс обязателен / опционален | Settings → Reports |
| Ставки VAT (с датой вступления) | Settings → VAT rates |
| Маппинг и игнор SKU | Settings → SKU mapping |
| Типы операций каналов, валютные правила, дефолты | Settings → Channel rules |
| Кто имеет доступ и с какой ролью | Settings → Team |

Правило разделения: **конфигурация — это то, что меняет параметры расчёта,
код — то, что меняет его смысл.** Расчётная математика намеренно не собирается
конструктором в интерфейсе: у отчёта бухгалтерская цена ошибки, и каждый
генератор при добавлении сверяется с эталоном построчно. Конструктор отчётов
дал бы гибкость ценой именно той гарантии, ради которой всё строилось.

## Добавить новый отчёт (~день работы)

1. **Миграция**: новое значение в enum `report_type`
   (`src/lib/db/schema.ts`, `drizzle-kit generate`).
2. **Определение** в `src/lib/reports/definitions.ts`: какие датасеты читает,
   месяц/квартал, `requiresEveryDataset`, `requiredRules`, тексты `needs`/`why`.
3. **Генератор** `src/lib/reports/<имя>.ts`: вход — строки журнала
   (`LedgerRow[]`) + правила + курсы, выход — листы `{name, rows}`.
   Деньги только через `decimal.js`.
4. **Ветка** в `build()` внутри `src/lib/reports/run.ts` (один `case`).
5. **Golden-тест**: собрать отчёт из реальных выгрузок и сверить с образцом,
   как в `tests/golden/`.

Всё остальное — карточка на Reports, доступность периодов, чеклист закрытия
месяца, вкл/выкл и required/optional в настройках, снапшоты правил и курсов —
подхватывается автоматически из определения.

## Добавить новый канал продаж (~1–2 дня)

Например, клиент начал продавать на Kaufland.

1. **Миграция**: значение в enum `dataset_id`.
2. **Профиль распознавания** в `src/lib/ingest/datasets.ts`: обязательные
   заголовки, где строка заголовков, из какой колонки читается период.
   (Файл опознаётся по содержимому, не по имени — так и держать.)
3. **Маппер** в `src/lib/ingest/mappers/`: из сырой строки в транзакцию
   (дата, тип, суммы, валюта, SKU). Непрочитанное число — флаг
   `needsAttention`, никогда не ноль молча.
4. **Правила канала** в `src/lib/reference/seed-data.ts`: типы операций,
   дефолты страны/схемы/номера продавца. «Restore missing defaults» доставит
   их существующим арендаторам.
5. **Подключить к отчёту**: добавить датасет в `datasets` нужного определения.
6. **Фикстуры**: `npm run fixtures -- "<файл>"` анонимизирует реальный экспорт;
   тесты на классификацию и маппинг по образцу существующих.

Чек-лист закрытия месяца, загрузки, сверка «файл → журнал», замещение при
перезаливке — всё это не знает названий каналов и заработает само.

## Добавить страну Amazon

Профиль языка уже может существовать (английский обслуживает UK и IE).
Если язык новый — профиль заголовков в `AMAZON_MONTHLY_PROFILES`, домен в
`AMAZON_MARKETPLACE_DOMAINS`, страна в `ZOHO_COUNTRIES` и ставка VAT в seed.

## Чего не делать

- Не расширять маппер «почти подходящего» канала под новый — у двух каналов
  всегда расходится семантика возвратов или комиссий, и это вылезает через
  месяц в цифрах.
- Не добавлять отчёт без golden-теста. Совпадение с эталоном — единственное
  определение «правильно», которое здесь есть.
